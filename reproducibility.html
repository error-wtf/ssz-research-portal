Derived repository practice

Programming rules

Names and domains

Use explicit names such as xi_strong, xi_weak, dilation, and normalized x=r/r_s. Every branch function documents its domain.

Units

Keep SI at public interfaces, label dimensionless ratios, avoid bare constants, and test dimensions. Convert to plotting units only at presentation boundaries.

Constants

Centralise G, c, φ and reference masses. Do not silently redefine r_s as GM/c² or change D to 1/(1+2Ξ).

Types and docs

Type public Python functions, add docstrings that include physical scope and units, and distinguish model, approximation and data-fit routines.

Errors and logs

Fail loudly on invalid domains, missing provenance or unit mismatches. Logs record commit, parameters, seed, tolerances and input checksums without secrets.

Plots

Axes carry quantities and units; comparisons identify branch and reference; uncertainty is visualised; captions state what the plot does not establish.

Numerical precision and tolerances

Precision by question

Use binary float for well-conditioned plots and ordinary tests, Decimal or arbitrary precision for sub-machine-epsilon phase differences, and symbolic algebra for limits and curvature identities.

Tolerance declaration

A tolerance must come from analytic truncation, floating-point propagation, solver convergence, or measurement uncertainty—not from adjusting until a test passes.

assert abs(xi_strong(1) - 0.801711847...) < declared_tolerance
assert xi_weak(10) == 0.05 within numerical tolerance
assert value, slope and curvature agree at x=1.8 and x=2.2
assert forbidden legacy formulas are rejected by claim gates

Release process

  1. Freeze canonical formula, branch and claim locks.
  2. Record clean/dirty status without overwriting unrelated work.
  3. Regenerate inventories and structured catalogues.
  4. Run repository tests in locked environments.
  5. Run content validation, internal-link checking and a secret scan.
  6. Review P0 wording, centre limits and observational caveats.
  7. Commit logically on a non-destructive branch.
  8. Deploy the exact reviewed commit through GitHub Pages.
  9. Verify the public URL and record the deployment commit.

Security and data hygiene

Never publish

Tokens, environment files, private remote URLs, authenticated URLs, absolute personal paths, SSH material, browser-side API credentials or raw error dumps containing secrets.

Public metadata only

GitHub metadata is fetched locally and written as safe static JSON. The browser never receives or needs a token.
